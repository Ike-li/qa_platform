# Product Status · QA 试点闭环

> 更新于 2026-06-04。本页是当前产品化试点边界，不替代 [`prd.md`](prd.md) 的目标态，也不替代 [`feature-catalog.md`](feature-catalog.md) 的功能细账。

## 目标用户

首批目标用户是 QA 工程师：已有一个自动化测试项目，需要把仓库、凭证、Pipeline、环境和 JUnit/Allure 结果接入平台，并稳定查看每日执行结果。

次级用户是 QA Lead / 测试经理：需要用轻量趋势、失败新增/恢复和 flaky 排除后的通过率判断一个 git ref 是否可进入下一步发布判断。

## 当前可承诺能力

- 项目接入：项目详情页提供接入状态面板，按 Git 配置、凭证状态、Pipeline、Environment、首次 Run 和通知可选项推导完成度；入口均复用现有配置页或触发弹窗。
- 首次试跑：用户可在项目详情页直接触发 Run，并在最近运行列表看到最新执行结果。
- 每日结果查看：项目详情页展示最近 Run；Run 详情页展示状态、失败摘要、测试结果、日志、报告/产物和重新触发入口。
- 失败排障：失败 Run 会突出失败摘要、失败/错误用例数、日志入口、报告/产物入口与 Re-run；失败用例展开后可跳到项目 Analytics 的单用例历史。
- Release 判断：Analytics 支持按 `git_ref` 过滤趋势和 flaky，提供 `release-summary` 摘要，包括 raw pass rate、flaky-adjusted pass rate、新增失败和恢复用例。
- 指标口径：试点指标先用现有数据计算，不新增埋点。

## 当前不承诺能力

- 完整跨分支 / 跨环境 diff 产品视图。
- GitLab / Gitee provider 的完整 webhook 事件矩阵。
- 多资源报告的统一报告中心体验。
- 长稳压测、完整容量墙和大规模队列公平性证据。
- 插件市场、Kubernetes Job 后端、多 Worker 节点管理等 Phase 4 能力。

## Beta 准入

Beta 可以接受以下限制：

- Webhook provider 以 GitHub push 主路径为主。
- 多资源报告体验仍偏弱，只要求 Run 详情页能进入报告和产物。
- 长稳压测尚未完成，但基础性能 smoke 和核心读写门禁要通过。
- 指标先采用可计算口径，不新增产品事件埋点。

Beta 必须满足：

- 一个 QA 工程师能从已有自动化项目完成接入、首次试跑并看到结果。
- 接入状态面板能明确显示 Git、凭证、Pipeline、Environment、首次 Run 的状态。
- 失败 Run 能从摘要进入日志、报告/产物、失败用例和重新触发。
- Analytics 能按目标 git ref 看趋势、flaky 和 release summary。

## GA 准入

GA 不能接受以下缺口：

- 首次接入没有明确引导。
- 核心 SLO 没有真实环境证据。
- Release 判断基础视图不可用。
- Run 详情页不能支撑失败定位的主流程。

GA 前需要补齐：

- 真实试点环境的 time-to-first-green-run、7 日内二次触发率、失败 Run 日志/产物查看率证据。
- 更清晰的接入验证动作证据，包括连接验证、JUnit 路径验证和试跑结果。
- 对多资源报告体验和长期稳定性压测给出明确达标或豁免结论。

## 试点准入条件

- 试点项目已有可运行的自动化测试和 JUnit XML 输出。
- 仓库访问方式明确：公开仓库、token 或 SSH key。
- 有一个可接受的基础镜像和运行资源上限。
- 试点团队愿意连续 7 天查看平台结果，并反馈接入、排障和 release 判断过程中的阻塞点。

## 成功指标

- `time-to-first-green-run`：从项目创建到首次无失败 Run 的时间。
- `7 日内二次触发率`：首次 Run 后 7 天内再次触发 Run 的项目占比。
- `失败 Run 的日志/产物查看率`：失败 Run 中至少查看日志或产物入口的占比。

辅助观察：

- 首次接入卡在哪个 checklist 项。
- 失败 Run 中是否进入单用例历史。
- Release 判断中目标 `git_ref` 与 baseline 对比是否足够回答“能不能继续发”。

## 下个里程碑

1. 收集 1-2 个真实 QA 项目的接入证据。
2. 把连接验证、JUnit 路径验证和试跑状态从“配置入口”升级为更明确的验证动作。
3. 补一轮真实环境的 Beta evidence：接入时长、首次 green、二次触发、失败排障路径。
4. 根据试点反馈决定是否投入完整跨分支 diff、多资源报告中心和更重的压测。
